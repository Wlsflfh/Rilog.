# Markdown 목차 및 글자 색상 설계

## 목표

게시글 독자가 긴 글의 구조를 빠르게 파악하고 원하는 제목으로 이동할 수 있게 한다. 작성자는 Markdown 편집 흐름을 유지하면서 선택한 글자에 안전하게 색상을 적용할 수 있어야 한다.

## 목차

- 본문 Markdown의 `#`, `##`, `###`, `####` 제목을 순서대로 추출한다.
- 제목이 하나도 없으면 목차 DOM과 빈 여백을 모두 생성하지 않는다.
- 데스크톱에서는 본문 오른쪽에 목차를 배치하고 스크롤 중에도 확인할 수 있도록 고정한다.
- 모바일에서는 좁은 화면을 침범하지 않도록 본문 위에 배치한다.
- `##`부터 `####`까지는 제목 단계에 따라 들여쓰기한다.
- 각 제목에는 문서 안에서 유일한 ID를 부여한다. 같은 제목이 반복되면 번호를 덧붙여 중복을 방지한다.
- 목차 항목을 누르면 해당 제목으로 부드럽게 이동한다.
- 목차 디자인은 네이비 세로선, 작은 제목, 절제된 텍스트 색상만 사용한다.

## 글자 색상

- Markdown 도구 모음에 자주 쓰는 기본 색상 5개와 자유 색상 선택기를 제공한다.
- 색상을 적용하면 선택 영역을 `<span style="color: #RRGGBB">내용</span>` 형식으로 감싼다.
- 선택 영역이 없으면 예시 문구를 삽입해 사용법을 알 수 있게 한다.
- 미리보기와 게시글 상세 화면 모두 동일한 색상 렌더러를 사용한다.
- 렌더러는 정확한 `#RGB` 또는 `#RRGGBB` 색상만 허용한다.
- 허용하지 않은 태그, 속성, 색상 값은 HTML로 실행하지 않고 일반 텍스트로 표시한다.
- 사용자 Markdown 렌더링에는 `innerHTML`을 사용하지 않는다.

## 구조

- `markdown.js`가 안전한 인라인 문법 렌더링, 제목 ID 생성, 목차용 제목 메타데이터를 담당한다.
- `app.js`가 렌더링된 제목 메타데이터로 목차 UI를 만들고 색상 도구의 편집 동작을 담당한다.
- `styles.css`가 오른쪽 목차 레이아웃, 반응형 이동, 목차 단계, 색상 도구 상태를 담당한다.
- 서버와 데이터베이스에는 기존처럼 Markdown 원문을 저장하므로 API와 스키마 변경은 없다.

## 접근성 및 반응형

- 목차는 `nav`와 명확한 접근성 이름을 사용한다.
- 목차 링크와 색상 선택 도구는 키보드로 조작할 수 있어야 한다.
- 색상 선택은 의미 전달의 유일한 수단으로 사용하지 않는다.
- 모바일 목차는 본문 위에서 자연스럽게 줄바꿈되며 가로 스크롤을 만들지 않는다.
- `prefers-reduced-motion` 환경에서는 부드러운 스크롤을 강제하지 않는다.

## 검증

- 제목이 없는 글에서 목차가 생성되지 않는지 확인한다.
- `#`부터 `####`까지 순서와 계층이 유지되는지 확인한다.
- 중복 제목의 이동 대상 ID가 서로 다른지 확인한다.
- 허용 색상은 렌더링되고 잘못된 색상 및 임의 HTML은 실행되지 않는지 확인한다.
- JavaScript 문법 검사, Spring 전체 테스트, 데스크톱과 모바일 레이아웃 검증을 수행한다.

## 범위 제외

- `#####` 이상의 제목은 본문에는 렌더링할 수 있지만 목차에는 포함하지 않는다.
- 목차의 현재 위치 자동 강조와 접기 기능은 이번 범위에 포함하지 않는다.
- 임의 CSS, 배경색, 글꼴 크기 변경은 지원하지 않는다.
