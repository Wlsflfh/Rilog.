# Rilog Dashboard Stats Design

## Goal

Rilog 사용자가 자신의 글이 조금씩 읽히고 반응을 얻고 있다는 감각을 받을 수 있는 개인 통계 대시보드를 제공한다.

## Scope

- Add authenticated API `GET /stats/me`.
- Add frontend route `#/dashboard`.
- Show total post count, total views, total likes, and total comments.
- Show recent 7-day view trend from `PostViewEvent`.
- Show top posts by views, likes, and comments.
- Show a soft achievement message derived from the user’s stats.

## Data Model

No new entity is required. The first version uses:

- `Post.viewCount`
- `Post.likeCount`
- `PostComment`
- `PostViewEvent`

`PostViewEvent` already records every detail view, so the 7-day trend can be generated by counting events belonging to the current user’s posts.

## API

`GET /stats/me`

Authenticated only.

Response shape:

```json
{
  "summary": {
    "postCount": 3,
    "totalViews": 120,
    "totalLikes": 14,
    "totalComments": 6
  },
  "dailyViews": [
    {"date": "2026-07-09", "viewCount": 2}
  ],
  "topViewedPosts": [],
  "topLikedPosts": [],
  "topCommentedPosts": [],
  "insightMessage": "이번 주에 12명이 당신의 글을 읽었어요."
}
```

## UX

The dashboard should feel quiet and motivating, not like an analytics product. Copy should focus on “발견되고 있음” and “기록이 쌓이고 있음”.

## Testing

- Service test for summary aggregation and 7-day trend filling missing dates with zero.
- Controller/security behavior is covered by existing authenticated route rules plus full integration tests.
- Frontend helper test for insight message and percentage bar width calculation.
